## Findings that settle open questions

- **Table 3 swap is real.** Our video-game graphs (200-299) average 8,637 nodes / 112,958 edges,
  which is the paper's *Download* row; our download graphs (400-499) match the paper's *Video Game*
  row. Every other row matches the paper exactly. Record this in the Data wiki page.
- **Attack edges match exactly:** 2,842,345 (3.166%), as in Table 2.
- **Distinct node ids: 5,044,482**, not the paper's 999,999 (Table 2 looks capped or wrong). This
  is almost exactly the authors' 5,045,000-row memory table. So global id compaction saves almost
  nothing here: node ids are effectively unique per graph. What does save memory is processing one
  graph at a time and resetting node memory between graphs (about 7k-9k nodes per graph). A
  100-dim float32 memory for all 5.04M nodes would be about 2 GB. Decide this in M3-01 and log it
  in ADR-0005.
- **No timestamps in the data.** The dataset README says preprocessing removed them, so file line
  order is the only time signal (supports D-04).
- **The simple baseline is very strong.** B1 (edge-type histogram distance) scores TP 97, TN 375,
  FP 0, FN 3: accuracy 0.994, precision 1.000, recall 0.970. Do-nothing scores accuracy 0.789.
  KAIROS has to beat 0.994, and the gap explanation should say StreamSpot's attack is easy to
  separate. This is a strong talking point for the presentation.

2. `Makefile`: `make baselines` no longer reruns the 3-minute stats pass when
   `results/graph_features.csv` already exists.
